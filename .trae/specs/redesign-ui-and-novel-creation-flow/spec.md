# UI 重新设计与小说创建智能问答流程 Spec

## Why
当前系统的"全文大纲"和"章节大纲"面板被限制在 320px 固定宽度的侧栏内，内容只能在小窗口里折叠显示，用户无法完整查看和二次修改，体验很差。小说创建目前仅是一个简单表单（标题/类型/简介/篇幅），没有引导式问答，收集的信息不足以驱动高质量的全文大纲生成，且创建后无法自动衔接大纲生成流程。知识图谱视图设计过于简陋，缺少按故事阶段（卷/章范围）查看角色演化的能力。提示词与整体架构在利用问答收集的丰富信息方面也存在断层。

## What Changes
- **重塑大纲面板布局**：全文大纲与章节大纲不再仅挤在 320px 侧栏里，新增"展开/全屏查看"能力，点击后在大内容区以完整、可编辑的形态展示，方便二次修改与确认。
- **重新设计知识图谱**：弃用当前简陋的力导向图 + 网格地图，改为分阶段（按卷/章范围）的角色信息展示视图，可选择不同阶段查看主角及其他角色的设定与关系演化；视觉上更精良。
- **小说创建改为智能问答系统**：将简单表单替换为多轮引导式问答对话界面，逐步询问小说名字、大致内容、写作方式、目标字数等，AI 据此扩写并保存到数据库；用户点击"确认"后自动开始全文大纲生成，确认全文大纲后再生成章节大纲。
- **检查并优化提示词与架构**：将问答采集的写作方式、目标字数等元数据传递给大纲 Agent 的提示词，保证大纲生成与用户意图一致。

## Impact
- Affected code:
  - `static/index.html`（侧栏与内容区结构调整、大纲展开入口）
  - `static/css/style.css`（布局、大纲全屏视图、知识图谱新样式、问答界面样式）
  - `static/js/app.js`（`showCreateNovelModal`/`createNovel`/`renderFullOutline`/`renderOutline` 重构）
  - `static/js/outline.js`（大纲展开/全屏编辑、确认流程衔接）
  - `static/js/knowledge-graph.js`（分阶段角色视图重写）
  - 新增 `static/js/novel-wizard.js`（小说创建智能问答流程）
  - `app/models/novel.py`（新增写作方式、目标字数等元数据字段）
  - `app/schemas/novel.py`（新增字段入参）
  - `app/agents/outline_agent.py`（提示词注入写作方式与目标字数）
  - `app/api/novels.py` / `app/services/novel_service.py`（支持问答扩写保存、自动触发大纲生成请求参数）

## ADDED Requirements

### Requirement: 大纲全屏展开查看与编辑
系统 SHALL 提供将全文大纲和章节大纲从侧栏小面板展开到主内容区全屏查看与编辑的能力。

#### Scenario: 用户展开全文大纲
- **WHEN** 用户在侧栏全文大纲面板点击"展开查看"按钮
- **THEN** 主内容区切换为全文大纲全屏视图，完整展示主题、核心冲突、故事弧线、各卷标题/范围/概要/核心角色/重大事件/基调，所有字段可编辑
- **AND** 视图提供"保存并返回"和"取消"操作

#### Scenario: 用户展开章节大纲
- **WHEN** 用户点击章节大纲"展开查看"
- **THEN** 主内容区切换为章节大纲全屏视图，以列表/卡片形式完整展示每章标题、情节摘要（完整）、关键事件、涉及人物、备注，支持逐章编辑与删除
- **AND** 编辑后需重新点击"确认大纲"

### Requirement: 分阶段角色知识图谱
系统 SHALL 提供按故事阶段（卷范围或自定义章范围）查看角色信息演化能力的知识图谱视图。

#### Scenario: 用户按阶段查看角色
- **WHEN** 用户打开知识图谱并选择"角色演化"视图
- **THEN** 顶部出现阶段选择器（列出各卷/各章范围阶段）
- **AND** 选择某阶段后，主区域显示该阶段内出场的所有角色，主角置顶突出，其他角色按戏份排列
- **AND** 每个角色卡片显示姓名、角色类型、该阶段内的设定描述、关系、出场章节
- **WHEN** 用户切换不同阶段
- **THEN** 角色列表与角色设定描述更新为该阶段的最新状态，呈现角色随剧情演化的变化

### Requirement: 小说创建智能问答系统
系统 SHALL 以多轮引导式问答对话替代简单表单创建小说。

#### Scenario: 用户通过问答创建小说
- **WHEN** 用户点击"新建小说"
- **THEN** 进入问答对话界面，AI 依次询问：小说名字、小说大致内容、写作方式（人称/叙事节奏/文风）、目标总字数与篇幅类型
- **WHEN** 用户回答完所有问题
- **THEN** AI 根据回答扩写为完整小说设定（含丰富简介、世界观雏形、主角设定建议）并展示给用户确认
- **WHEN** 用户点击"确认"
- **THEN** 设定保存到数据库，并自动开始全文大纲生成，无需额外手动点击

#### Scenario: 全文大纲确认后衔接章节大纲
- **WHEN** 用户查看、修改并确认全文大纲
- **THEN** 系统"生成章节大纲"按钮可用并提示用户，用户点击即生成章节大纲

### Requirement: 大纲提示词注入写作元数据
系统 SHALL 在生成全文大纲时将问答采集的写作方式和目标字数注入提示词。

#### Scenario: 大纲生成使用写作元数据
- **WHEN** 触发全文大纲生成
- **THEN** 大纲 Agent 的用户消息包含目标字数与写作方式描述，生成的大纲体积与文风与用户意图一致

## MODIFIED Requirements

### Requirement: 全文大纲面板与确认流程
全文大纲面板在侧栏中以紧凑摘要形式存在，提供"展开查看"入口进入全屏编辑；编辑保存后需重新确认；确认后写作中仍可随时展开编辑，编辑后回到未确认状态。

### Requirement: 章节大纲面板与确认流程
章节大纲面板在侧栏中以列表摘要形式存在，提供"展开查看"入口进入全屏逐章编辑与删除；编辑/删除后需重新确认大纲。

### Requirement: 知识图谱视图
知识图谱提供"角色演化"（分阶段角色，默认）、"关系网络"（力导向图）、"世界观地图"三种视图切换，弃用当前简陋设计，统一为精良视觉风格。

## REMOVED Requirements

### Requirement: 简单表单式创建小说
**Reason**: 替换为智能问答系统，能采集更丰富的写作意图信息。
**Migration**: 旧的 `showCreateNovelModal` 表单逻辑由问答流程 `novel-wizard.js` 取代；后端 `NovelCreate` schema 新增字段保持向后兼容（旧字段保留可选）。
